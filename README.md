# Vehicle Routing Problem (VRP) Simulator

A C# implementation of the famous **Vehicle Routing Problem (VRP)**. This project calculates the most efficient delivery routes for a fleet of vehicles aiming to fulfill a set of orders while minimizing travel costs.

**Disclaimer on Authorship:**  
> The core backend logic, pathfinding, and route optimization algorithms were written by me. The Graphical User Interface (GUI / `SimulationVisualizer`), however, is fully generated by Claude.ai.

## Overview

The Vehicle Routing Problem is a complex combinatorial optimization challenge. This execution determines the fastest and most cost-effective way to deliver all orders by accounting for:
*   **Order Size:** The storage capacity required for each specific delivery.
*   **Vehicle Capacity:** The maximum cargo weight/volume each truck can carry.
*   **Fuel/Distance Constraints:** The maximum distance a truck can travel before needing to return to the depot to refuel.
*   **Fleet Size:** The total number of available trucks in the depot.
*   **Terrain Costs:** Variable movement costs across the grid (e.g., roads, rough terrain, walls).

## Features & Algorithms

### 1. Clarke-Wright Savings Algorithm
To determine which orders should be grouped together on a single truck's route, the backend utilizes a variation of the **Clarke-Wright Savings Algorithm**. 
*   It calculates the distance "saved" by linking two delivery points together rather than serving them on separate trips from the central depot.
*   The system sorts these potential savings and aggressively merges routes (`TryCreateNewRoute`, `TryAppendToRoute`, `TryMergeExistingRoutes`) as long as capacity and fuel constraints are not violated.

### 2. A* (A-Star) Pathfinding
While the Savings algorithm determines *which* stops a truck should make, the **A* Pathfinding algorithm** determines *how* the truck physically navigates there.
*   Operates on a 2D grid.
*   Fully respects terrain weights: normal roads (cost: 1), rough terrain (cost: 5), and impassable obstacles/walls (cost: 99).
*   Pre-computes a complete `DistanceMatrix` at initialization to ensure the dispatch logic runs instantly without re-calculating paths.

### 3. Tick-Based State Machine
The trucks operate on a continuous tick-based simulation. Each vehicle manages its own state:
*   `Idle`: Waiting for a new route dispatch at the depot.
*   `Loading`: Spending time proportional to the order size preparing the cargo.
*   `Driving`: Moving node-by-node along the A* generated path, draining fuel.
*   `Refueling`: Recharging fuel reserves at the central depot upon route completion.

## Project Structure

*   **`main.cs`**: The brain of the operation. Holds the grid layout, dummy data initialization, and the core `DispatchWave()` logic that orchestrates the Clarke-Wright algorithm.
*   **`Truck.cs` & `Order.cs`**: Data models representing the fleet and the deliveries. `Truck` contains the `Tick()` logic to update physical positions and states.
*   **`AstarPathfinding.cs`**: A standalone namespace containing the A* grid search logic and priority queue evaluation.
*   **`SimulationVisualizer.cs`**: (Generated by Claude.ai) The visual frontend layer that hooks into `main.CurrentTick` to render the grid, trucks, and depots.

## How to Run

By default, the application is set up to run with the GUI. 

To run the simulation visually:
1. Ensure the `SimulationVisualizer` is active in `Main()`.
2. The `app.Init()` method will load the dummy data and wait for the visualizer to call `TickSimulation()`.

To run the simulation exclusively in the console (Headless Backend Mode):
1. Navigate to `public static void Main()`.
2. Uncomment `app.Run();` and comment out the visualizer initialization.
3. In the `main` class, swap the `Init()` method back to `Run()` and uncomment the `while(true)` loop to watch the console log the truck movements and dispatch waves in real-time.
